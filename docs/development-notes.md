# 第一版开发中发现的真实问题

## 工具重复调用

首个真实 Ollama 演示中，模型已经顺序取得 DNS、TCP、HTTP 503 观测，仍重新调用同样三个工具，
最后达到八轮上限。原始记录保存在 `results/first-live-model/`。

改进：每项检查成功取得结果后从可选工具中移除；前置失败或 HTTP 检查结束后进入最终输出阶段。
最终阶段使用 JSON Schema 约束结构。对应回归测试确认最终阶段不再提供重复检查工具。

## 数学与诊断类别误判

一次结构有效的结果把 HTTP 503 判为 slow_response，还把实际 `0.79 ms` 写为超过 `800 ms`。
该结果保存在 `results/verified-live-model/`，目录名只表示做过真实调用，不表示结论正确。

改进：工具明确返回 http_error、slow、scheme、tls_checked。
所有 A/B/C 组共用观测一致性检查，拒绝与实际状态和布尔量冲突的分类，反馈给模型修正。
程序不直接替换模型答案；首次草稿、错误草稿和修正次数均保留。
首次草稿准确率与最终准确率分开，避免用自动校验掩盖小模型能力限制。
后续正常案例还发现模型反复无视反馈，所以修正阶段增加动态 JSON 类别候选约束。
候选只由当前实际观测决定，不读取 expected 标签，始终允许 insufficient_evidence。
这属于各组共用的程序护栏；最终成绩必须与首次草稿成绩一起解释。

当前一致性检查只能发现阶段和类别冲突，不能保证自由文本中每个因果解释都正确。
尤其应人工检查“不适用的 TLS 解释”“将服务等待误判为拥塞”和未经观测支持的根因断言。

## 评测口径

评测先采集本地故障服务的真实观测，再在 A/B/C 之间回放同一份数据。
DNS 失败和 HTTP 观测缺失案例明确标为 synthetic_fixture。
故障类型标签只进入评分器，不进入模型提示。
规则模式仅用于工具测试，不能作为 LLM、Agent 或 Skill 优越性的证据。

## 2026-11-03 检查后的修正

- 实时工具、回放工具及 Agent 工具会话使用相同的前置条件检查。未获得成功的 DNS/TCP 观测时，后续调用返回 not_ready，不执行工具，不产生证据，也不记为有效调用。
- 回放工具记录本次已调用的检查；预先存在的原始记录不再代表模型已经取得相应证据。Agent 会话也独立检查模型实际取得的证据，避免复用 provider 的缓存绕过顺序。
- 工具参数必须为空对象。列表、null、布尔值、数值和非空对象均被拒绝；模型返回的 JSON 字符串参数解析后同样校验。
- 显式端口 0 被拒绝；仅在没有指定端口时选择 HTTP 80 或 HTTPS 443。
- 前置阶段观测不可用时停止采集，进入最终结论，避免继续调用无法满足前置条件的工具。
- 公共提示和调查 Skill 明确区分“证据反驳”和“尚未验证”。HTTP 观测缺失不能排除 HTTP/TLS/慢响应故障，也不能作为重启或重新部署的依据。这是提示改进，不能保证自由文本语义完全正确，仍需真实模型复测与人工审阅。
- README 补充历史实验的 4B 模型复现命令，默认 0.8B 配置保留。历史 Trace、评分与清单保持原样，当前修改的收益尚未重新测量。

验证：`python -B -m unittest discover -s tests -v`，19 个测试全部通过，包含七类故障案例和新增回归检查；未重新执行 Ollama A/B/C 实验。

## 2026-11-03 根据实际运行截图修正文字矛盾

截图中 HTTP 200、响应等待 134.36 ms、阈值 800 ms，最终类别虽然是 normal，模型摘要仍声称响应超过阈值，并将没有阈值的 TLS 耗时解释为偏慢。此前只校验类别，没有核对摘要及其他文字字段。

- 增加 `src/validation.py`：最终摘要与类别短句绑定，耗时数值和比较由程序展示；模型其他字段不得重复耗时数值或大小比较。
- 增加有限规则检查，覆盖未观测到慢响应却声称响应慢、没有阈值却声称 TLS 慢、IP 输入声称 DNS 正常、HTTP 请求声称 TLS 正常、已获得 HTTP 状态却声称观测缺失，以及部分不恰当的证书修复、延长超时和重启/部署建议。
- 规则区分已排除项与尚未验证项，也允许有条件的复测建议及“不要重启”等否定表达。规则仅覆盖已知表达，不能充当通用自然语言语义验证器。
- 文字校验失败后进入明确标注的程序候选修正：由观测生成阶段、摘要和其他字段的候选，通过 JSON Schema 和 Python 端共同校验。已有明确阶段时，不允许在此修正阶段改为证据不足。原始草稿不覆盖，持续失败仍记录为执行失败。
- 报告说明摘要模板与程序辅助；JSON 保存 `narrative_policy`、实际使用的候选和 `narrative_repair_used`，评分另记辅助修正次数。这些结果不能作为模型未经帮助的分类或自由解释能力成绩，旧版实验需单独保留。

验证：33 个单元测试全部通过。真实 `qwen3.5:0.8b` 回放截图中的相同网站观测后，输出正常类别和短摘要；没有重新探测该外部网站。本地真实 HTTP 503 故障复测在程序候选修正后输出 http_error，引用 E3，未再误报响应慢或 TLS 正常。这两项模型复测在内存中完成，未新建评测报告，也没有重跑完整 A/B/C 实验。

## 2026-11-03 网页工作台

新增 React 前端、本机 Python HTTP 服务和启动入口，覆盖网站诊断、七类故障实验、A/B/C 评测、历史报告和运行设置。所有检测仍使用原有工具与模型协议；前端不生成虚假结果或进度。

诊断和评测增加可选事件回调，供网页显示真实工具调用、模型调用和校验步骤，原命令行接口保持兼容。任务串行执行，结果和任务记录存于 results/web；停止操作为协作式取消，等待当前调用结束，保留已完成的观测。重启后的未完成任务标记为中断。

HTTP 服务仅绑定 127.0.0.1，校验 Host/Origin、输入参数和结果文件范围。网页不会运行任意命令，也不修改网络配置。Windows 启动脚本可直接打开浏览器，构建文件已包含，运行不依赖 Node。

新增 HTTP 层回归测试：参数与本机 Ollama 地址校验、真实故障任务与报告下载、结果持久化、规则评测、停止语义、缺少模型服务、跨来源请求和目录穿越拒绝。总计 42 个测试通过。视觉及浏览器验收记录见 docs/frontend-design.md。
